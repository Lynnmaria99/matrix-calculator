## 产品定位与完成标准

**定位：**离线优先的数学学习桌面工具，重点是透明的数值计算、可检查的输入和直观图示；不以通用 CAS（计算机代数系统）为首要目标。

达到“日常可用”至少意味着：

1. 常用线性代数任务可从输入到结果/解释/导出顺利完成。
2. 输入错误、维度问题、数值近似、复数结果和适用范围有清晰提示。
3. 用户能保存/复用输入，且结果可复制到作业笔记。
4. 安装、启动、升级方式对非 Python 用户清楚。
5. 新功能有核心算法测试和 UI 测试；核心不依赖 GUI。

### 2. 学习体验与稳定性 `[ ]`

**目标：**让已有计算结果更容易理解、复核和复用。第一阶段合并后先做此阶段，OCR/符号代数暂不阻塞它。

- [ ] 对页面加轻量引导：输入格式、需要的矩阵形状、结果含义、一个可运行示例。
- [ ] 统一错误提示：维度不兼容、非方阵、奇异矩阵、空/非数值单元格、函数定义域错误。
- [ ] 明确区分精确输入与浮点近似；结果页展示精度/容差说明，避免把数值零或近似特征值说成精确结论。
- [ ] 审核特征分解复数、病态矩阵、秩判断和最小二乘等边界，并在 UI 中解释适用条件。
- [ ] 结果复制格式一致；评估添加“复制为 Markdown 数学公式/LaTeX”的价值，先审计现有格式化与导出能力。
- [ ] 收集真实使用中最常见的 3 个任务，按频率决定 UI 优先级。

**验收：**新用户按页面提示能完成示例；典型错误有明确修正建议；结果中明确标注近似性质；复制到笔记可读。

### 3. LaTeX 与数学表达式互操作 `[ ]`

**目标：**先实现受控、可验证的矩阵输入/结果输出，不宣称支持任意 LaTeX。

- [ ] 功能盘点：检查桌面、CLI、Streamlit 的复制/导出控件和格式化函数，明确当前究竟输出什么格式。
- [ ] 定义首版输入语法：建议支持 `bmatrix`/`pmatrix`、整数、小数、负号、简单 `\frac{p}{q}`；不接受宏、对齐环境或任意命令。
- [ ] 在独立纯函数中解析 LaTeX 矩阵；给出行列位置级错误信息。
- [ ] 导入后填入现有矩阵编辑器，用户确认后才计算；保留手工编辑路径。
- [ ] 增加“复制为 LaTeX”输出选项，分别测试方阵、长方阵、负数、小数、分数和特殊数值。
- [ ] 如需微积分函数 LaTeX 输入，另立子任务；避免把矩阵解析与通用符号解析合并。

**验收：**支持语法有文档；合法输入往返稳定；不支持的命令能准确报错；解析器不执行用户代码；UI 可预览并人工确认。

### 4. OCR 单矩阵输入 `[ ]`

**目标：**把图片变成可校对的矩阵草稿，用户确认后才参与计算。

- [ ] 先确定主要来源：教材/PDF 截图、屏幕截图或手机照片；首版只承诺一种清晰印刷体来源。
- [ ] 做技术验证：本地离线方案、安装体积、许可证、Windows 支持、识别速度和准确率；确认前不锁定 OCR 引擎。
- [ ] UX 流程：截图/图片载入 → 裁剪矩阵 → 识别行列与单元格 → 标记低置信度 → 填入矩阵网格 → 用户校正/确认。
- [ ] 定义错误恢复：行列数不确定、括号/负号/小数点混淆、空白单元格、分数识别失败时，不静默猜测。
- [ ] 建立小型匿名/合成测试集；记录整矩阵准确率及单元格错误率，而非只看 OCR 演示成功。
- [ ] OCR 作为可选依赖或独立 extra；用户图片默认本地处理，不上传第三方。

**首版范围限制：**不识别整页题目、自然语言、运算符、手写内容；不自动执行识别结果。

**验收：**对声明支持的图片类型有可重复的准确率目标；低置信度结果可见；完整人工校对流程可用；没有无声错算路径。

### 5. 微积分教学扩展 `[ ]`

**目标：**在当前数值微积分 MVP 上提供可视化与方法比较，明确与符号计算的区别。

- [ ] 显示采样点/切线位置/积分区间，并解释数值导数和数值积分的近似性。
- [ ] 支持对比中点、梯形、辛普森等方法及分割数影响；显示误差估计或收敛趋势。
- [ ] 处理函数定义域、奇点、端点无穷值和振荡函数等情况。
- [ ] 只有在确有精确求导/积分需求时才引入 SymPy；把符号结果与数值结果分栏展示。

**验收：**用户能看懂方法、参数和近似误差；异常区间不会让 UI 崩溃或给出误导结果。

### 6. 发布与可维护性 `[ ]`

- [ ] 决定桌面发行目标（Windows 优先或跨平台）并试做独立安装包。

## 优先级建议

| 优先级 | 工作 | 原因 |
|---|---|---|
| P0 | 第二阶段：学习引导、边界提示、格式化/导出审计 | 第一阶段已合并，下一步提升日常可用性 |
| P1 | LaTeX 矩阵输入 + LaTeX 结果复制 | 语法可控，能改善输入和作业笔记衔接 |
| P2 | OCR 单矩阵草稿 | 依赖技术验证，识别错误必须可校对 |
| P3 | 微积分误差教学 | 在核心输入/结果体验稳定后扩展 |
| P4 | 独立安装包与发布流程 | 面向非 Python 用户交付 |

## 每阶段的工作约定

1. 一个阶段一个分支/PR；不把多个大方向塞进一个 PR。
2. 先写清验收条件，再实现；新 UI 复用核心纯函数。
3. 运行测试、静态检查和入口冒烟；记录实际结果，不能以本地通过代替 CI。
4. OCR/LaTeX 解析始终允许用户检查输入，遇到不确定内容要报错而不是猜测。
5. 完成一阶段后更新本计划状态与实际发现，再决定下一阶段范围。
